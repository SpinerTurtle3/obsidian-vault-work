Interview questions derived from the [[Interviews/Job Descriptions/Sr. Software Engineer.md|Sr. Software Engineer JD]]. Grouped by theme so a scorecard can be built against each section later.

---

## 1. Backend Development (C#, .NET, APIs)

- Walk me through a RESTful API you designed from scratch. What did the service contract look like, and how did you decide on it?
- This role spans .NET Framework (primarily) and .NET Core (select apps). Tell me about a time you worked across both. What trips people up when moving between them?
- Describe a defect you diagnosed in a system you didn't originally build. How did you approach understanding the code before touching it?
- How do you approach designing a data model or service contract to be "clean, extensible, and documented"? Give a concrete example.
- Tell me about a time you had to pay down technical debt in a live application without disrupting the people using it.

## 2. Frontend Development (Angular / React)

- You'll work in both Angular and React depending on the application. Which do you have deeper experience with, and what's your experience level in the other?
- Describe a time you had to build a UI feature with no design spec — how did you define the UX yourself, and how did you validate it with stakeholders?
- What's your approach to maintaining frontend code in an older application with established (maybe outdated) patterns — do you conform to existing patterns or modernize as you go? How do you decide?

## 3. Database & SQL

- Walk me through a complex query or stored procedure you've written. What made it complex, and how did you approach performance?
- Tell me about a schema design or migration you owned. What tradeoffs did you consider?
- Describe a time you diagnosed a SQL Server performance issue. What was your process for narrowing down the cause?

## 4. Deployment, CI/CD & Cloud

- Describe your hands-on experience deploying and troubleshooting applications in IIS. What's a tricky IIS issue you've resolved?
- Walk me through a CI/CD pipeline you've built or maintained — Azure DevOps, GitHub Actions, or otherwise. What did it automate, and what did you have to work around?
- What's your experience with Azure services (App Service, Azure SQL, Key Vault, Function Apps, Static Web Apps)? Give an example of using one in production.
- This team is expanding its Azure footprint. Tell me about a time you contributed to a cloud modernization or migration effort — what was the starting state, and what did you move toward?
- What's your experience with REST API auth patterns like OAuth 2.0? Describe a time you implemented or consumed an OAuth-secured API.

## 5. Systems Thinking & Architecture

- Tell me about a time a change you made in one part of a system had ripple effects elsewhere. How did you catch it (or how did you find out)?
- How do you approach working across "a portfolio of applications with varying ages, patterns, and levels of documentation"? Walk me through your first-week approach to an unfamiliar codebase.
- Describe a technical design document you wrote. What did you include to make sure someone else could pick up the work?
- Give an example of a time requirements were ambiguous or incomplete. How did you get to a reasonable solution without waiting for perfect information?

## 6. Ownership & Execution

- Tell me about something you owned "front to back" — from requirements conversation through deployment. What was hardest about owning the whole lifecycle?
- Describe a time you flagged a risk or blocker early. What made you raise it when you did, and how did it land?
- Tell me about a time you picked up work that wasn't clearly yours to own. What made you take it, and how did it turn out?

## 7. Collaboration & Communication

- Tell me about a time you had to explain a technical problem to a non-technical stakeholder. How did you adjust your explanation?
- Conversely, describe a time you had to translate a business need into a technical solution. What did that conversation look like?
- What's your approach to code review — both giving and receiving feedback? Tell me about a time review feedback changed your approach.
- Tell me about a disagreement with a stakeholder or teammate about how to build something. How was it resolved?

## 8. Quality & Documentation

- What does "code others can maintain" mean to you in practice? Give an example of a decision you made specifically for future maintainability.
- Tell me about documentation you wrote (runbook, design doc, inline comments) that you know got used by someone else later. What made it effective?
- How do you balance shipping quickly against writing tests, docs, and clean code when working in a lean team with real deadlines?

## 9. Closing / Candidate-Led

- What about this role or team is most appealing to you, and what gives you pause?
- What questions do you have about the team, the application portfolio, or how work gets prioritized?
